# Boss Around 🧡

Μια απλή **PWA** για ανάθεση και παρακολούθηση εργασιών — από το αφεντικό προς τους υπαλλήλους.
A simple **PWA** for assigning and tracking tasks from a business owner to employees.

- 📋 Ο ιδιοκτήτης αναθέτει εργασίες· κάθε υπάλληλος βλέπει τη δική του λίστα (και προαιρετικά όλων).
- ⭐ Καταστάσεις: *Εκκρεμεί / Σε εξέλιξη / Σε αναμονή / Ολοκληρώθηκε / Ακυρώθηκε* + σήμανση με **αστέρι**.
- 💬 Συνομιλία (chat) ανά εργασία μεταξύ υπαλλήλου και αφεντικού.
- 🔔 Ειδοποιήσεις σε πραγματικό χρόνο (in‑app + συσκευής).
- 👥 Σύνδεση χρηστών με **κωδικό πρόσκλησης** *και* με **email**.
- 🌙 Σκοτεινό/φωτεινό θέμα, ⚙️ σελίδα ρυθμίσεων, 🇬🇷 Ελληνικά (+ English).

Stack: static frontend (HTML/CSS/vanilla JS) on **GitHub Pages** + **Supabase** (Postgres, Auth, Realtime, Row‑Level Security).

---

## 1) Set up Supabase (the database)

1. Create a free project at <https://supabase.com>.
2. Open **SQL Editor** → **New query**, paste the entire contents of [`schema.sql`](schema.sql), and click **Run**.
   This creates all tables, security policies, triggers and functions.
3. **Auth settings** (`Authentication → Sign In / Providers`): the **Email** provider is on by default.
   - For quick testing you can turn **off** *"Confirm email"* so you can sign in immediately.
   - Keep it **on** for production (users confirm via the link Supabase emails them).
4. **Redirect URLs** (`Authentication → URL Configuration`): add your GitHub Pages address, e.g.
   `https://<username>.github.io/<repo>/` — needed for the email magic‑link / confirmation to return to the app.
5. Copy your keys from **Project Settings → API**:
   - **Project URL**
   - **anon public** key

> The **anon key is meant to be public** — it’s safe in a public repo. All data access is restricted by the Row‑Level Security policies in `schema.sql`, so each person only ever sees their own organization.

## 2) Add your keys

Open [`config.js`](config.js) and paste the two values:

```js
window.BOSS_AROUND_CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT-ref.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR-ANON-PUBLIC-KEY'
};
```

## 3) Publish to GitHub Pages

1. Create a repository and upload **all files in this folder** (keep the structure flat).
2. In the repo: **Settings → Pages → Build and deployment → Source = "Deploy from a branch"**, pick `main` / root.
3. Open the published URL. On mobile, use the browser’s **“Add to Home Screen”** to install it as an app.

That’s it. 🎉

## How it works

| Role | What they can do |
|---|---|
| **Αφεντικό / Boss** | Creates the business, assigns/edits/deletes tasks, sees everyone’s board, manages the team (invite code + email invites), chats on any task. |
| **Υπάλληλος / Employee** | Joins with a code or email invite, sees their own list (and can switch to *All*), changes status & stars on their tasks, chats with the boss. |

**Two ways to connect employees**
- **Code:** Settings → share the 6‑character invite code; the employee enters it on the onboarding screen.
- **Email:** Settings → *Invite by email*. When that person signs up with the same email, the invite appears on their onboarding screen to accept.

**Notifications** are generated by database triggers (new task, status change, new comment) and pushed live via Supabase Realtime. With device permission granted, alerts also show on the device when the app isn’t focused.

## Security notes

- Every table has **Row‑Level Security** enabled; users can only read/write rows for their own organization.
- Employees are blocked (at the database level) from promoting themselves to *boss* or editing protected task fields — they can only change `status` and `starred` on their own tasks.
- Task creation and deletion are restricted to the boss.
- Per‑task chat is visible only to the boss and the task’s assignee.

## Notes & limits

- **Push notifications while the app is fully closed** require a push service (VAPID keys + a sender, e.g. a Supabase Edge Function). The current build covers in‑app and device notifications while the app is open/backgrounded; the service worker is already wired for `notificationclick`.
- Email *sending* for invites is intentionally not done from the browser (that needs a service‑role key). The email‑invite flow works by matching the address at sign‑up, so no secret key is ever exposed.
